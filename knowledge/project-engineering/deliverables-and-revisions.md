# Engineering Deliverables, Revisions and Change Control

## Engineering deliverables

Deliverables are the documents and drawings an engineering team produces:
design basis, PFDs, P&IDs, datasheets, specifications, calculations,
layouts, isometrics, line lists, instrument index, MTOs, requisitions and
so on. They are tracked in a **deliverables list / document register** with
planned and actual issue dates.

## Document issue status

Documents progress through issue purposes. Names vary by company, but a
common sequence is:

| Code | Meaning |
|---|---|
| IFR | Issued for Review (internal or client comment) |
| IFA | Issued for Approval |
| AFD | Approved for Design |
| IFC | Issued for Construction |
| AB / As-built | Updated to reflect what was actually built |

Only the **current approved revision** — for construction, normally IFC —
should be used for fabrication or construction.

## Revision control

- Each issue gets a revision code (e.g. A, B, C for pre-approval issues;
  0, 1, 2 for approved/construction issues — conventions vary).
- Changes are marked with revision clouds/triangles and described in the revision block.
- Superseded revisions are withdrawn from use.

## Queries and changes

- **RFI (Request for Information)** — a contractor asks for clarification of a design document.
- **TQ (Technical Query)** — a formal technical question, often to the
  client or vendor, requiring a documented answer.
- **Deviation / concession request** — permission to depart from a specified requirement.
- **MOC (Management of Change)** — the formal process for reviewing,
  approving and documenting changes to design or operations, including
  their safety impact.

## Why it matters

Using the wrong revision, or an unapproved deviation, is a frequent cause of
rework. Answers from this assistant are **not** a substitute for the
current approved project documents.
